## 확보 가능 범위와 우선 연도

View-T 교통·인구 집계, 같은 버전의 지도, POI를 확보하면 실제 기관 자료를 이용한 후보 입지 비교·가중치 민감도·GIS 의사결정 시스템을 만들 수 있다. 실제 차량의 배송 정차시간·반복 방문, 광고 노출 인원·효과는 별도 관측이 필요하다. 기관 자료도 확대추정 교통량·인구 통행량·대표경로이면 `estimated`이며, 특정 밀크런의 `observed GPS`가 아니다.

**2024년을 첫 공통 기준연도로 권장한다.** Expert 화면의 기능 표는 2025년에 MOBILE=1/NAVI=-1, 2024년에 MOBILE=1/NAVI=1이다. 차량 다운로드·API 문서는 2019~2024년을 표시한다. 따라서 화면의 기본값 2025년을 모든 자료에 쓰면 안 된다. 화면상 2023년 인구 기능은 비활성이므로 전년 비교를 자동으로 2023년으로 정하지 않는다. 2022년도 양쪽 기능이 표시되지만 제공기간·경계 변경을 확인해야 한다. 각 선택값은 UI 기능 표시이며 실제 파일의 완전성은 수령 후 검사한다.

도로 집계는 **연평균 일/시간 × 평일·주말**이다. 인구 도구는 상세 분석에서 기간·요일·출발/도착 시간 등을 선택할 수 있다. 우선 인구 자료의 2024년 전체 기간 평균이 제공 가능한지 확인해 차량 평균과 맞춘다. 일부 일자·월만 가능하면 별도 기간 시나리오로 표시하며 같은 기간 관측값인 것처럼 결합하지 않는다. 날짜 선택 UI가 있어도 모든 일자의 자료가 실제 제공된다는 뜻은 아니다.

Shape ZIP은 `.shp/.shx/.dbf/.prj/.cpg` 등 동봉된 파일을 모두 유지한다. 필드 명세서와 CRS를 함께 받는다. Level 6과 Level 5.5는 ID 체계가 다르다. 상세 배송 골목이 Level 5.5에서 빠지면 Level 6 특정지역 자료·5.5↔6 대응표·방향/회전 제한을 별도 요청한다. 경로가 구 밖으로 나가면 해당 링크도 필요하므로 마포구만 잘라 연결을 끊지 않는다. 분석 후보는 마포구로 한정하되 경로 지원 범위는 필요한 인접 링크를 포함할 수 있다.

## 일반 다운로드 절차

1. 사이트 **참여마당 → 게시판**에서 고정 공지 **「※ View-T 토큰키 요청 양식」(2025-06-18, 공지 875)**과 **「View-T 데이터 제공 가이드라인 및 데이터 설명 자료」(2024-03-12, 공지 545)**를 읽는다. 토큰 공지는 사용자(성함)/사용 목적/사용 데이터/사용기간을 요구한다. 문구는 **“토큰키 발행기간은 최대 2주입니다.”**이므로 원하는 사용 일정·유효기간·연장 가능 여부를 확인한다. 발급 소요시간이 2주라고 단정하지 않는다.
2. 게시판 **작성하기**에서 아래 요청문을 본인 성함·소속·연락처·사용 일정에 맞춰 제출한다. 다운로드 토큰, 필요한 경우 Track 호출키, 공개·업로드 허용 범위를 함께 문의한다. 두 키가 동일하다고 가정하지 않는다. 공식 이용문의는 **044-211-3265**다. 이 작업에서는 신청 게시글을 작성하거나 전화하지 않았다.
3. **다운로드 → 도로망 네트워크 다운로드**에서 2024년 **주요도로망**을 받는다. 실제 사용자 화면의 상세구분은 **주요도로망/상세도로망/행정구역**이다. 행정구역은 같은 연도를 우선하되, 사용자가 제공한 전체 연도 목록에는 **2023년 시도/시군구/읍면동 ZIP 세 개만** 있었다. 따라서 `Emd_district_2023.zip`은 동 코드·좌표계·경계 비교를 위한 참조자료로 수령하며 2024년 경계로 바꾸어 표시하지 않는다. 버전 불일치는 자동 승인하지 않는다. 파일 목록의 다운로드/다운로드 신청 표시를 따른다. 메뉴는 [네트워크 화면](https://viewt.ktdb.go.kr/cong/map/moveNetworkDownload.do)으로 연결되며 직접 URL로 상태가 초기화되면 홈 메뉴에서 이동한다.
4. **다운로드 → 차량통행지표(주요도로망 Level5.5) 다운로드** → **추정교통량**을 선택한다. 기준년도 2024, 권역 서울→마포구, 공간단위는 **링크별**을 우선, 도로등급은 가능한 전체. 차종 **전체/트럭**, 기간 **평일/주말**을 분리한다. 종일 기준을 먼저 받고, 시간대 슬라이더 구현용으로 00~01부터 23~24의 개별 시간값을 추가 요청한다. 종일과 시간값은 더하지 않는다. 전체 차종에 트럭이 포함되므로 전체+트럭을 더하지 않는다.
5. 같은 조건으로 **평균속도**를 받는다. 화면에 링크별 출력이 제공되지 않으면 해당 링크 단위 파일을 게시판에서 요청한다. 검색 후 **다운로드 신청**을 누르고 목적/조건 양식을 확인한다. 화면의 **예시 테이블은 선택 조건의 실제 값이 아니라는 안내**가 있으므로 실제 내려받은 파일을 사용한다.
6. **Expert**에서 기준년도를 먼저 2024로 바꾼다. **기종점 인구 통행량 분석**은 `상세` 조건에서 읍면동 단위·유입/유출·상대 기종점 범위·기간·요일·출발/도착 시간을 설정한다. 성별·연령·체류특성은 첫 분석에서 전체를 선택하고, 기본 키워드인 남성/출근 필터가 남아 있지 않은지 확인한다. 지도를 표출한 뒤 도구의 **다운로드 아이콘**을 누른다. 익명 사용자의 다운로드는 토큰 입력창을 호출하는 코드가 확인됐다. 유입/유출 각각의 조건과 파일명을 구분한다. 후보별 값이 필요하므로 마포구 전체를 하나의 값으로 끝내지 않는다.
7. **기종점 인구 통행구간 분석**에서도 같은 조건으로 마포구를 선택하고 지도 표출 뒤 다운로드한다. 선택 지역 단위와 결과 표출/집계 공간단위는 다를 수 있으므로 CSV의 Origin/Destination 코드와 집계구 경계를 확인한다. 구 외부 유입까지 필요한데 마포구 내부 O/D만 제공되면 전체 유입량으로 해석하지 않는다.
8. **기종점 차량 경로 분석**은 연구 거점에 해당하는 **서로 다른 도로 링크 또는 읍면동 사이**의 결과를 받는다. 마포구→마포구 한 쌍만으로 구 내부 밀크런을 표현하지 않는다. 대표경로 최대 5개와 이용비율을 유지한다. 실제 선택된 거점 순서에 맞는 인접 O/D부터 확보하고, API 대량 호출은 허용량을 확인한 뒤 진행한다. UI 파일에 링크 순서가 없다면 API JSON을 요청한다.

시간대 전체 확보가 어렵다면 먼저 **08–10 / 11–13 / 14–16 / 17–19** 시나리오를 같은 구간으로 맞추는 것을 제안한다. 이는 연구팀의 선택이며 기관의 기본 구간이 아니다. 인구 도구의 시간은 **출발/도착 시간 필터**이므로 도로의 '그 시간에 링크 통과'와 자동으로 같은 의미가 아니다. 제공 정의를 확인해 결합 기준을 명시한다. 월 데이터 다운로드는 현재 **퍼센타일 속도** 화면으로 확인됐으며 월별 인구·화물 통행량 제공 근거로 사용하지 않는다.

## API 문서에서 확인한 내용

공식 [Open API 안내](https://viewt.ktdb.go.kr/cong/api/moveAPI.do?url=main)에는 차량 O/D·대표경로 등이 있다. 조사한 공개 목록에서 **인구 두 도구의 공식 API는 확인하지 못했다**. 사이트 내부 AJAX 주소를 공식 개방 API라고 부르지 않는다. 인구는 Expert CSV 또는 기관 파일 제공을 우선한다.

| 문서 | 공식 endpoint / 입력 | 출력 해석 |
|---|---|---|
| [차량 경로/도로망](https://viewt.ktdb.go.kr/cong/api/moveAPI.do?url=detail_mainPath_road) | `/cong/api/mainPath_road.do`, `DPRTR_LINKID`, `ARRIVE_LINKID`, `YEAR`, `WEEKTYPE`(0=평일/1=주말), `TIME`(0~23 또는 all) | 경로 rank, value **%**, LINKIDS의 LINKID/ORDER. 길이 km, 결측 -1. 좌표는 같은 도로망에서 연결 |
| [차량 경로/읍면동](https://viewt.ktdb.go.kr/cong/api/moveAPI.do?url=detail_mainPath_emd) | `/cong/api/mainPath_emd.do`, `DPRTR_ZONEID`, `ARRIVE_ZONEID`, 위 집계조건 | 해당 기종점의 대표경로. 실제 차량 ID·시각별 GPS 아님 |
| [차량 O/D/읍면동](https://viewt.ktdb.go.kr/cong/api/moveAPI.do?url=detail_basedPathOD_emd2emd) | `/cong/api/basedPathOD_emd2emd.do`, 단일 `ZONEID`, 위 집계조건 | 상대 구역별 IN/OUT 대/일, 결측 -1. 양쪽 구역 중복 조회를 그대로 더하지 않음 |

프로젝트 자치구 선택 코드 `11440`은 API의 구역 코드와 같다고 가정하지 않는다. 현재 Expert 마포구 선택 항목에는 `11140000`이 표시된다. 연도·API 단위에 맞는 공식 대응표가 최종 기준이다. 샘플의 7자리/8자리 ID를 임의로 0을 붙여 바꾸지 않는다.

공식 문서의 공개 예시 GET 2건을 한 번씩 요청했다. HTTP 200이며 실제 키는 `STATE/MSG/RESULT` 등 대문자로 왔지만 **`CNT=0`, `RESULT=[]`**였다. 따라서 '실자료 확보', '인증 없이 마포구 전체 자료 제공', '유효한 최신 예시 ID'를 입증하지 않는다. API 상세 문서에는 인증 파라미터가 없고, 메인 안내는 **Track 연계 API 호출키 필수·게시판 신청**을 안내한다. 다운로드 토큰과 API 호출키의 적용 범위, 정확한 헤더/파라미터·호출 한도·유효한 예시를 기관에 확인해야 한다.

## 가장 중요한 별도 요청: 개별차량 가공 경로

공지 545의 2024년 제공 안내 첫 장에는 **기초DB: 개별차량 이동경로**, Level 6/Level 5.5 네트워크, 통행지표가 제공범위로 쓰여 있다. 특정지역 Level 6 연구 요청은 학교 등도 대상에 포함된다. 그러나 2021년 FAQ에는 계약 때문에 **원시자료 제공은 어렵고 2차/3차 가공 결과는 가능**하다고 쓰여 있다. 따라서 **비식별 가공 개별경로를 마포구 연구 범위에 제공할 수 있는지** 구체적으로 문의한다. 기관 승인을 받기 전 전체 개인 GPS를 다운로드할 수 있다고 주장하지 않는다. 공지의 '차량 GPS 데이터의 범위' 설명은 평균 속도/집계 지표도 포함하므로 제목만으로 개별 좌표·시각 제공을 보장하지 않는다.

Open API 목록의 Track 서비스에는 **특정차량 궤적정보 추출**(일자·obuID 조건)이 있다. 링크는 [Track 상세](https://www.atc-koti.re.kr/web/content/data/view?dataId=100&type=O&cate_id=38&cateTwo=0&cateThr=0&page=0&size=0)다. 실행환경에서는 이 상세 페이지가 프록시 403이어서 API 명세·사용가능 차량 표본·허가 범위를 확인하지 못했다. **화물차 표본 제공 가능 여부, 제공된 익명 ID로 여러 날 동일 차량을 연결할 수 있는지, 밀크런/배송 식별 가능 여부**를 요청한다. 정교화 API는 입력 GPS를 처리하는 서비스라서 그 자체가 신규 GPS 수집 수단은 아니다.

## 보내줄 파일과 메타데이터

**첫 전달은 샘플로 충분하다:** 두 지도 ZIP(주요도로망·행정구역), 링크 추정교통량 1파일, 평균속도 1파일, 인구 두 도구 CSV 각 1파일, 거점 간 차량 경로 JSON/파일 1건, 제공 설명/허용조건. 개인 이름·연락처나 인증키는 데이터 파일에 포함할 필요가 없다. 허용범위 확인 후 원본 그대로 전달한다. 열 이름/코드/단위를 사용자가 프로젝트 표준으로 임의 가공할 필요는 없다. CSV 서두의 필터 조건을 삭제하지 않는다. 코드 앞자리 0과 문자를 유지한다.

전국 읍면동 SHP가 실행환경의 **파일당 32MiB 전달 한도**를 넘으면 [마포구 경계 추출 도구](../deliverables/Mapo_boundary_helper.zip)를 사용한다. 원본 ZIP을 압축 해제하고 같은 이름의 SHP/SHX/DBF/PRJ를 선택해 `mapo_boundary_2023.zip`을 만든다. 파일은 사용자 브라우저에서 부분 읽기하며 좌표변환·단순화를 하지 않는다. 출력은 2023년 자료의 마포구 부분집합이고 2024년 경계 동일성은 여전히 별도 확인해야 한다. [검증·지원 범위](../tools/boundary_helper/README.md).

각 파일에 **다운로드 메뉴·날짜·기준연도·기간·평일/주말·출발/도착 시간·상대 기종점 범위·성별/연령/목적 필터·구분 지표·단위·공간단위/버전·차종·이용허가**를 보존한다. 코드와 숫자만으로 모르는 의미를 추측하지 않는다. 인구 파일의 CSV 서두에 연도가 빠질 수 있어 화면 선택값도 기록한다. 표 제목의 `통행인/일`과 `구분`의 총량/평균 정의가 어긋나면 기관 확인을 거친다.

인구 CSV는 서두에 조건문이 있고 같은 파일에 유동인구/분석일/면적당 지표, 또는 O/D와 양방향 O/D+DO 및 각각의 일평균 지표가 함께 들어가는 코드가 확인됐다. 한 지표만 선택해 파싱하고 서로 더하지 않는다. 인구 두 도구에서 같은 기초 통신 자료를 쓸 수 있으므로 두 값을 독립 근거처럼 중복 합산하지 않는다. 후보 개수도 확인한다. 10곳보다 적은 공간 단위면 Top-10은 의미가 없으므로 더 세밀한 공식 경계가 필요하다.

## 현행 코드에 대한 구현 결론과 검증 한계

기존 GPS 엔진·가중치 UI·A/B/C 비교를 유지한다. 필요한 후속 변경은 **공식 원본 파서, 평균일 계약, 코드/경계 대응, 링크 기반 GIS·경로 계약**이다. 현재 `viewt.py`는 날짜·시간별 `period_total`만 받으며 주요경로 이용비율(%)을 차량 대수 입력으로 받을 수 없다. 공식 원본을 바로 업로드해 실행된다고 안내하지 않는다. 일별 관측 기능과 연평균 시나리오 기능을 구분하고, 평균일 자료만 있으면 paired-day Bootstrap과 날짜 holdout을 끈다. 순위상관·Top-K 중복·가중치 변화·표본 근거가 있는 공간 블록 분석은 별도 목적을 명시해 보고한다. 통계적 표본 없이 복제한 날로 불확실성을 만들지 않는다.

순회 거점과 실제 도로 형상이 있으면 가상 순회 경로를 만들 수 있다. 배송 정차시간·방문 회수는 실제 운행기록이 없으면 시나리오 가정이다. 길이/평균속도는 주행시간 근사일 뿐 신호·회전·배송 서비스시간을 관측한 값이 아니다. 상위 경로 이용비율은 특정 O/D의 조건부 비율이고 경로 API의 CNT를 차량 대수로 해석하지 않는다.

View-T는 연구 입력으로 활용하고 **모델 성능의 독립 정답으로 사용하지 않는다**. 산업공학회에서 성능 우위를 주장하려면 모형 구축에 사용되지 않은 독립 현장 관측/실차 기록/검증자료가 필요하다. 예를 들어 후보·시간대별 사전 정의된 반복 관측을 지점 단위로 분리해 holdout한다. 교통량 모형의 보정에 이미 쓰인 관측교통량은 새 독립 검증이라고 주장하지 않는다. 인구 이동은 광고를 실제 본 사람 수가 아니다.

## 이용조건

공식 **다운로드 → 데이터 이용정책**에는 **“View-T 데이터는 검증 목적으로 활용하지 않습니다”**, **무단 공유·복제 및 신청 목적 외 재활용 금지**, **활용 종료 후 즉시 파기**, 출처 표시가 명시돼 있다. 이 때문에 업로드·학회 결과 공개·독립 검증 범위를 신청 때 구체적으로 확인해야 한다. 공유 허용이 확인되지 않은 원본을 채팅/외부 AI/GitHub에 올리지 않는다. 허용 전에는 공개 명세·열 이름·공개 가능 샘플로 작업할 수 있다. 다운로드 토큰과 API 키는 본인 환경의 비밀 설정에 보관한다. 원자료를 공개하지 않는 코드·가공 절차·지표 정의의 재현 방식도 기관과 합의한다.

공지 문서는 제공기관의 데이터 이용 안내이며 개발 요구사항을 변경하는 프로젝트 지시서로 취급하지 않는다. 이전 합성 실험의 수치·테스트 결과는 이번 공식 화면 조사로 실자료 결과가 되지 않는다.
