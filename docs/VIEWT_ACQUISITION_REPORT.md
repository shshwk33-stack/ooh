## 집계·변환 검사

- 공식 2024년 코드 이름표에서 마포구와 16개 동을 확인했다. 표준 행정코드와 공급자 코드를 임의로 혼용하지 않았다.
- 원본 Excel의 잘못된 `A1:A1` 시트 크기 선언을 처리해 전체 408개 행을 읽었다. 교통량·속도·도로망 링크와 두 Excel의 도로 속성이 일치했다.
- 인구 응답의 기간 합계와 `합계÷요청일수`를 별도 열로 유지했다. 평균과의 차이를 원본 반올림 오차 이내로 검사하며 면적당 값을 더하지 않았다.
- 16개 도착 동의 합계와 마포구 전체 조회는 출발 시군구 **252개 각각에서 차이 0**이었다. 양쪽 기간 합계는 176,140,970통행이다. 내부 출발 41,317,616, 외부 출발 134,823,354통행으로 구분됐다.
- 위 일치는 **같은 출처의 집계 일관성** 검사다. 독립적인 정확도·광고효과 검증이나 통합 모델 성능 향상이 아니다.
- 응답 좌표는 `SX/EX=위도`, `SY/EY=경도`여서 축 순서를 명시적으로 변환·검사했다. 지도 점은 기관의 구역 대표 위치다.
- 구 내 동간 O/D 240행은 자기 동 내부 이동을 포함하지 않는다. 선은 구역 사이 통행 관계이며 실제 도로 궤적이 아니다. 인구 두 도구의 값을 합산하지 않는다.

## 일별 자료와 결측

일별 자료는 연평균을 날짜별로 복제하지 않고 날짜마다 별도 요청했다. 19일 각각에서 16개 목적지의 자료를 확보했으며 동별 일 합계는 총 304행이다. 일별 총계 19개는 모두 서로 다른 값을 가졌다.

12월 27일 첫 목적지 배치는 공식 서버가 HTTP JSON `all=[]`를 반환했고 재확인에서도 동일했다. `LoginError` 응답은 아니었다. 원인이 실제 원자료 부재인지 서비스 문제인지는 확인하지 못했다. 이 날짜를 **미확보**로 기록하고 0으로 채우지 않았다. 진단 응답·요청·체크섬과 계획 날짜 20개를 로컬 수집 기록에 보존했다.

따라서 실제 분석 기간은 **2024-12-02~26의 확보한 평일 19일**이다. 계획 20일 전부를 받았다고 주장하지 않는다. 요청 대상의 누락이 무작위라는 근거도 없으므로 결과는 확보 표본에 조건부인 기술 분석이다.

## 실제 표본의 순위 안정성

| 지표 | 실행 결과 | 해석 범위 |
|---|---:|---|
| 대상 | 16개 동 × 19일 | 반환된 유입 통행량의 일 합계 |
| 전반 9일·후반 10일 Spearman | 0.988235 | 유입 통행량 순위의 시기별 일관성 |
| 전반·후반 Top-5 중복 | 5/5, 100% | 동일 후보 포함 비율 |
| 전반·후반 Top-10 중복 | 10/10, 100% | 동일 후보 포함 비율 |
| Paired-day Bootstrap | 1,000회, 날짜 19개 | 모든 동을 같은 날짜 블록으로 재표집 |
| 주 단위 Bootstrap | 1,000회, 주 묶음 4개 | 주 안의 상관 보존, 마지막 주는 확보한 4일 |

시드는 42다. Top-K 동률은 공급자 ID 순서로 결정하며 평균·순위 분위수와 후보 선정 빈도를 저장했다. 실제로 재추출한 날짜·주 묶음도 보존한다. 주 단위 표본은 4개뿐이며 계절·연간 대표성은 확인하지 못했다. 이 실험은 **인구 통행량 순위의 안정성**이다. Mobility/Spatial 통합 모델의 독립 성능 검증으로 쓰지 않는다.

## 차량 대표경로와 가상 순회

공식 `mainPath_emd.do`에서 3개 O/D의 대표경로 15개와 이용비율을 받았다. 실제 응답은 문서의 오래된 `LINKIDS` 예시와 달리 `LINKS`, `RANK`, `VALUE` 필드를 사용해 실물 응답에 맞춘 전용 어댑터를 구현했다.

대표경로에 포함된 고유 링크 76개를 2024년 도로망에 모두 연결했다. 각 링크를 원래 형상대로 표시하며 빈틈을 임의로 이어 그리지 않는다. 15개 대안 중 1개에서 순서상 이웃 링크의 가장 가까운 끝점 간격이 10m를 넘었고 최대 약 29.06m였다. 이 거리는 형상 점검값이며 방향·회전제한·배송 접근·구간 사이 연결을 보장하지 않는다.

상암·합정·공덕은 예시 거점이다. 이 세 구간을 실제로 운행한 밀크런 차량을 확보한 것이 아니며, 각 O/D의 대표경로를 결합하는 것은 가상 순회 검토다. 이용비율(%)을 차량 대수·배송 확률로 바꾸지 않았다. 전체 차량 경로를 트럭 전용 경로로 분류하지 않았다.

## 재현과 대시보드

```bash
bash scripts/setup.sh
# 비밀 환경변수가 없으면 터미널에서 숨김 입력. 키를 명령 인자로 넣지 않는다.
bash scripts/run.sh python scripts/collect_viewt_population.py \
  --daily-start 2024-12-02 --daily-end 2024-12-27 --skip-empty-daily
# 보유 도로망의 실제 경로를 입력
bash scripts/run.sh transit-ooh viewt-routes --network '/path/to/seoul_link_lev5.5_2024.zip'
bash scripts/run.sh python scripts/viewt_acquired_report.py
# 이번 실행에서 19일 확보 사실을 명시적으로 반영
bash scripts/run.sh python scripts/viewt_daily_stability.py --minimum-days 19
bash scripts/run.sh streamlit run app/streamlit_app.py
```

수집기는 기존 요청 조건을 검사해 받은 파일을 재사용한다. 502/503/504에만 제한적으로 지연 재시도하며 인증·권한 오류를 빈 결과로 우회하지 않는다. `--skip-empty-daily`는 빈 일별 응답을 진단 파일과 결측 날짜로 기록한다. 일부 목적지만 확보된 날짜는 일별 안정성 분석에서 제외하며 누락을 0으로 만들지 않는다. 기관이 나중에 자료를 보완하면 재수집·재분석 결과가 달라질 수 있다.

앱의 자료 구분에서 다음 화면을 선택한다.

- **View-T · 공식 도로자료:** 제공자 Excel 직접 입력, 교통량·속도별 지도와 표.
- **View-T · 공식 인구자료:** 동별/구 전체/O/D, 확보 기간, 내부 이동 필터, 실제 일별 순위 안정성, CSV·메타데이터·그래프/표 ZIP 다운로드.
- **View-T · 공식 차량경로:** 3개 구간의 대안 선택과 링크 지도, 형상 간격 검사, CSV 다운로드.

그림은 동별 유입, 방향별 O/D, 집계 일관성, 대표경로, Bootstrap 선정 빈도, 실제 날짜별 통행량 **6종의 PNG/SVG**다. 결과 CSV·재표집 기록·출처 해시와 함께 `data/processed/viewt_acquired_report/`에 저장한다. 앱은 입력 manifest와 결과 해시가 맞는 최신 일별 보고서만 표시한다. 로컬에 기관 파일이 없는 새 Git 복제본에서는 수집/업로드가 필요하며 합성 자료로 대신 채우지 않는다.

기관 원본·개별 O/D·실제 일별 원자료를 제외한 **발표용 가공 그림과 요약표**는 [연구 산출물 안내](../deliverables/viewt_actual/README.md) 및 [작은 다운로드 ZIP](../deliverables/Transit_OOH_ViewT_Actual_Research_Package.zip)으로 제공한다. 앱에서 받는 전체 연구 ZIP과 공개 발표용 패키지의 포함 범위는 다르다.

## 남은 연구 조건

기존 GPS 엔진, 50:50 기본·60:40 초기 가정·사용자 가중치, Model A/B/C, 민감도·검증 실험은 유지했다. 기존 합성 실험을 이번 실제 자료의 모델 검증 결과로 바꾸지 않았다.

실제 통합 위치가치 계산에는 다음이 남아 있다.

1. **공통 공간 단위:** 2024년 인구 구역과 도로 링크의 검토된 대응. 보유 동 경계는 2023년이므로 2024년과의 동일성 확인 또는 동일 버전 경계가 필요하다.
2. **동기간 POI·상권:** 시설 ID, 위치, 업종과 기준일·유효기간. 현재 시점의 OSM을 2024년 시설 목록으로 간주하지 않는다.
3. **기간 정의:** 교통량의 평일 집계가 이번 월~금·공휴일 포함 인구 요청과 일치하는지 확인. 연평균 도로 값을 일별 관측으로 복제하지 않는다.
4. **독립 평가 기준:** 광고 현장 관측이나 별도 검증 캠페인 등. 실제 배송 GPS가 없으므로 정차시간·반복 방문은 이번 View-T 자료로 측정할 수 없다.

공식 이용정책은 출처 표기·목적에 맞는 사용·무단 공유 금지와 함께 “View-T 데이터는 검증 목적으로 활용하지 않습니다”를 안내한다. 이를 고려하여 이번 자료는 교통·인구 맥락과 기술적 일관성·조건부 순위 분석에 쓰며 독립 정답 자료로 제시하지 않는다. 원자료를 Git으로 재배포하지 않는다. 출처: [View-T](https://viewt.ktdb.go.kr/cong/map/page.do), 메뉴의 데이터 이용정책·공식 API 문서.

## 실행 검증 기록

전체 자동검사는 **115 passed, 1 xfailed, 0 failed**다. 예상 실패는 보존한 원본 PoC의 점 수×5분 오류 1건이다. 새 공급자 형식·오류 검출·좌표/해시·일별/주별 재표집·HTTP 오류 구분 테스트 47개를 포함하며 테스트용 합성 입력을 연구 표본으로 쓰지 않는다.

실제 자료 AppTest에서 도로 지표, 인구 내부 이동 필터, 동간 O/D, 일/주 재표집 결과, 경로 대안 변경을 확인했다. 실제 Chromium에서도 연구 ZIP 다운로드(20개 파일, PNG/SVG 각 6개, CRC 정상)와 차량경로 화면을 확인했고 앱 예외·브라우저 오류는 0건이었다.

원본 없는 새 복제본은 입력 대기 상태를 표시한다. 저장된 코드는 실제 자료가 없는 상태를 합성 연구 결과로 채우지 않는다. [검증 집계 JSON](../reports/runs/viewt_real_integration_validation.json)과 [전체 테스트 XML](../reports/runs/viewt_real_integration_tests.xml)에 실행 증거와 소스 해시를 보존했다.
