확인일: 2026-11-02. 첨부 지시문의 마지막 실행 범위인 **Phase 0 진단 후, 확보된 구조·자료로 Phase 1을 수행**했다. 기존 UI 재설계와 연구결과 임의 생성은 하지 않았다.

## 실제 자료와 품질

고정 출처: `southkorea/seoul-maps@dbb1dcde2e3c9937684c5a44ab9301888ad63ee6`. README에서 KOSTAT 2013 유래를 확인했다. 원문 URL·SHA·선정/제외 자료와 사용조건 확인 범위는 [공개자료 조사](PUBLIC_DATA_RESEARCH.md)에 있다.

| 실행 | 입력 | 선택 | 필수속성 결측 | 개별 위상 | 최대 왕복오차 |
|---|---:|---:|---|---|---|
| 자치구 | 25개·1,374좌표 | 마포구 `11140`, 1개 | 0 | 25/25 유효 | 1.42×10⁻¹⁴도 |
| 행정동 | 423개·3,654좌표 | `11140` 접두사, 16개 | 0 | 423/423 유효 | 2.13×10⁻¹⁴도 |

행정동 자료에는 이름 `신사동`이 다른 코드에서 반복된다. 코드 중복은 없으며 이름이 같다는 이유로 병합하지 않고 경고로 남겼다. 두 파일 모두 CRS 필드가 없어 EPSG:4326을 **명시적 처리 계약**으로 적용했다. 공식 투영원본의 CRS 선언을 복구했다고 주장하지 않는다.

단순화된 마포구의 파생 면적은 약 24.573km², 16동 면적 합은 약 24.428km²다. 서로 다른 간소화 정도의 역사적 형상 결과로 공식 면적 통계가 아니다. 동 사이의 중첩·빈틈·부모 경계와 합집합의 차이까지 자동 조정하거나 검증한 것은 아니다. 16동 둘레 합은 공유 내부 경계를 포함한다.

미러 README의 Apache v2.0 선언은 확보했지만 원기관 약관은 별도 재확인하지 못했다. 원천 메타데이터의 `license=UNKNOWN`과 미러 선언을 분리해 기록하고 품질 경고를 유지했다.

## 합성 입력의 역할

`mapo-gps-seed42`는 **SYNTHETIC 72행, 차량 2대, 가상 3일**이다. 2013 마포구 형상 내부의 개념 좌표 시퀀스이며 실제 도로를 따르는 운행기록이 아니다. 고정 seed 42, 생성법·가상 날짜·경계 SHA를 기록했고 모든 행에 분류를 남겼다.

검증 모듈은 실측 GPS CSV를 받을 수 있는 형식·품질 계약을 제공하지만, 현재 실측 기록을 확보한 것은 아니다. 정차·방문 이벤트·경로 반복성·M/S/V·Bootstrap을 계산하지 않았다. 합성 입력으로 기존 대시보드 점수나 고정 안정성 값을 교체하지 않았다.

## 실행과 재현성

실행 명령:

```sh
.venv-analysis/bin/python scripts/run_phase1.py --output research_data/runs/phase1-verified
.venv-analysis/bin/python scripts/run_phase1.py --output research_data/runs/phase1-reproduced
```

동일 입력으로 두 실행을 완료했다. 실제 실행시각·환경의 `execution.json`을 제외한 **결정적 산출물 16개**가 바이트 단위로 같았다.

| 처리 | run_id |
|---|---|
| 마포구 | `4630c10de816506df7d273e6` |
| 마포 16동 | `3ac24940d0f85fac6dc17f18` |
| 합성 GPS 검증 | `072c1dba318dc2c960c4dee5a422cb2ee6dc20e6d04a93092fb13463fda45d88` |

확인된 결과 사본은 [results/summary.json](results/summary.json)과 하위 세 폴더에 있다. 원본 위치는 메타데이터에서 추적할 수 있다. 설치·개별 명령·출력 해석은 [실행 방법](README.md)을 따른다.

음수·NaN·좌표 범위·열린 ring·자기교차·CRS/기준연도/해시 불일치, 중복 JSON 키·코드·GPS 관측, 시간대·속도 이상, 합성의 실측 재표기, 기존 출력 덮어쓰기, 입력 누락을 검사했다. 내보내기 도중 실패를 주입해 부분 GeoJSON/CSV·manifest를 폐기하고 실패 보고서·로그만 남기는 것도 확인했다.

실제 도로 링크 매칭·원천 기반 M/S·공간결합·모델별 상관·Bootstrap은 이번 단계에서 구현/실행하지 않았다. 이 항목을 테스트 통과로 보고하지 않는다. 기존 UI의 화면 수치도 실제 연구결과로 전환된 것이 아니다.

## 기존 프로젝트 영향

- `src/`, `dashboard/src/`, 기존 `tests/`, `dashboard/tests/`, `public/`의 내용은 변경하지 않았다.
- 기존 점수식·시간계수·예시 데이터·API 인증정보·DB 구조 변경 및 데이터 삭제는 없다.
- 새 의존성은 별도 `.venv-analysis`와 `requirements-analysis.txt`로 분리했다.
- 변경한 기존 문서는 루트 README와 `.gitignore`다. 연구 CLI 실행법·생성물 제외 규칙을 추가했다.
- `dist-dashboard/`와 화면 캡처는 회귀 검증 과정에서 재생성한 빌드/검사 산출물이다.
- 백업과 기준 커밋, 진단 커밋, Phase 1 구현·검증 커밋으로 변경 이력을 분리했다.

## 다음 단계와 필요한 자료

1. **Phase 2:** 사용조건·기준시점·좌표계가 확인된 실제 도로 링크를 확보하고, 기존 UI 지도에 실제 경계를 연결한다. 현재 경계는 구형 자료이므로 최신 연구기간과의 정합성도 검토한다.
2. **실제 이동자료가 계속 없을 때:** 합성 운행 시나리오의 목적·경로 제약·표본 구조를 먼저 정하고 별도 탐색 실험을 수행한다. 이 결과는 실측 배송행태를 검증한 연구로 해석하지 않는다.
3. **Phase 3:** 같은 기간·공간 단위의 인구/POI/상권 자료와 실제 GPS 또는 명시적 대리지표가 있을 때 원천 기반 M/S 및 정규화 기준을 정한다.
4. **Phase 4:** 독립성을 고려한 차량·운행일 표본이 있을 때 모델 비교·순위상관·Top-K·Bootstrap을 수행한다.

필요한 실제 GPS는 차량 ID·offset 포함 timestamp·경도·위도·수집방법·사용조건이며, View-T는 공식 상품 명세·정상 원본 응답 또는 CSV·집계 단위·기간이 필요하다. 교통량을 특정 배송차량 GPS로 바꾸어 사용하지 않는다.
