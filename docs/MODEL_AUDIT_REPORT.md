## 위치가치 점수와 사용자가 정하는 가중치

GPS 모드의 Mobility는 기존 비정차 존재시간·정차시간·방문횟수의 정규화 평균을 유지한다. View-T 표준 파일 모드는 차량 통행량 대리지표를 사용하며 GPS 정차·방문을 측정했다고 표시하지 않는다. 두 모드의 값은 같은 측정량이 아니다.

표준 파일 모드에서는 다음과 같다.

- A(Spatial) = β × 정규화 인구 통행량 + (1−β) × 정규화 POI.
- B(Mobility proxy) = 정규화 차량 통행량.
- C(Integrated) = α × B + (1−α) × A.

α 기본값 .5, 과거 비교값 .6이다. 둘 다 검증된 최적값이 아니다. β 기본값 .7도 초기 연구 가정이며 이번에 화면·CLI에서 변경 가능하게 했다. 정규화는 같은 후보군에서 고정하고 가중치를 비교한다. min–max의 상수 특성은 0이다. 정규화가 0이라는 이유로 해당 지역의 실제 활동이 없다고 해석하지 않는다.

후보 i,j의 선형 점수 `A + α(B−A)`가 만나는 α를 구한다. 유효 교차점 사이에서는 순서가 일정하므로 구간 중간과 모든 경계점을 검사한다. float64 계산과 14자리 반올림 동점 규칙을 사용하므로 기호대수 수준의 무한 정밀도를 주장하지 않는다. 후보 1~500개를 지원하며 더 큰 자료는 계산 전에 범위를 좁혀야 한다.

`top5_weight_share`는 α의 전체 범위 중 해당 후보가 Top-5에 들어가는 **구간 길이 비율**이다. 선호 가중치를 균등하게 검토한 의사결정 지표이며 경험적 선정확률이 아니다. 동점은 ID 순으로 운영상 선택하되 `necessary_share`와 `possible_share`를 함께 제공해 동점 때문에 포함 여부가 달라지는 범위를 드러낸다.

`worst_regret`는 각 가중치의 1위와 해당 후보 사이 점수 차이의 최댓값이다. 선형 점수들의 최대값에서 한 선형 점수를 뺀 함수는 볼록하므로 구간 양 끝에서 최대를 구할 수 있다. 이 값을 최소화하는 후보를 표시하되 보편적 최적 입지라고 부르지 않는다. Pareto 후보는 A,B가 동시에 다른 후보보다 낮지는 않은 후보이며 실제 성과 우위의 증거는 아니다.

## 실제 실행한 모델 실험 — 합성 데이터

기존 마포구 중심 **합성 예제**를 유지했다. seed 42, 가상 후보 16개, 2025-10-01부터 14일, α=.5, β=.7이다. 아래 수치는 실제 마포구 후보 평가가 아니다.

| 실험 | 결과 |
|---|---:|
| A–C Spearman | 0.579412 |
| A–C Top-5 중복 | 3/5, 60% |
| 전체 가중치의 일정 순위 구간 | 36개 |
| 기본 점수의 Pareto 후보 | 1개 |
| 최소 최대후회값 후보 | 합성 DEMO-11440-05 |
| 정규화·내부 비중 15개 설정의 기본 Top-5 중복 | 80~100% |
| 날짜/주별 Bootstrap | 각각 1,000회, seed 42 |
| 주별 묶음 | 3개, 일부 주 불완전 |

이 예제는 한 후보가 두 성분에서 지배적인 구조다. 그 후보의 안정성을 모델의 우수성으로 주장하지 않는다. 순위 변화는 의사결정의 차이를 보여 주며 성능 향상률이 아니다. 주 묶음 3개는 특히 작으므로 결과는 조건부 설명용이다.

정규화는 `minmax`, `log1p_minmax`, 평균 동점 순위를 사용한 `percentile` 3종을, β는 0/.3/.5/.7/1을 비교했다. 사용자 β가 이외 값이면 추가로 포함한다. 로그는 극단값의 영향을 줄이고 순위 변환은 크기 차이 정보를 버리므로 세 방식 중 항상 더 좋은 방식은 없다. 동일 시나리오의 특성·점수·교차 구간·정규화별 순위·재표집 날짜를 CSV로 보존했다.

## 실제 자료에서 계산한 것

공식 2024년 `sqlite:zone_emd_2024` 지도 레이어를 제한된 서울 범위로 조회했다. 공식 Expert 연도 설정의 `V_YEAR=2024`와 `TxMapGlobal.js`의 레이어 정의를 확인했다. 제공자 2024 코드 이름표와 일치하는 16개 동만 선택했다. 출처 URL·요청 조건·원본 SHA256을 로컬에 보존한다. 명칭이나 가까운 좌표만 보고 다른 버전 자료를 합치지 않는다.

경로와 도로는 연도·평일·종일 요청과 동일 도로망 SHA256을 검사한다. 형상의 WGS84 측지 길이를 사용해:

- 길이 가중 교통량 = Σ(링크 길이 × 해당 링크의 연평균 교통량) / Σ길이.
- 시간 대리지표 = Σ(링크 길이 / 해당 링크의 연평균 속도).

전자는 경로의 도로 교통 맥락이며 동일 차량을 여러 번 포함할 수 있다. 후자는 평균 속도의 역수를 대입한 시나리오다. **평균 속도의 역수는 실제 평균 이동시간과 같지 않다.** 배송차량 속도, 정차, 신호대기, 거점 연결, 회전제한을 반영한 운행시간이 아니다.

합정→공덕의 2위 대안에 포함된 `8902776` 링크는 보유 408개 교통·속도 표에 없다. 이 경로의 교통량·시간 합성치를 결측으로 남겼다. 나머지 14개 경로도 실제 운행 가능성이 검증된 밀크런 경로는 아니다. 이용비율은 기관 반환 비율 그대로 보존하고 배송 차량 대수나 노출량으로 바꾸지 않는다.

## 독립 검증 도구와 아직 필요한 증거

[현장 검증 사용법](FIELD_VALIDATION_GUIDE.md)에 점수 고정→관측→비교 절차가 있다. 실제 파일이 들어오기 전에는 독립 평가 결과를 생성하지 않는다. 프로토콜 해시는 변경 검사용이지 실제 관측·독립성을 인증하는 전자서명이 아니다.

완성도 높은 연구 제출을 위해 남은 것은 다음 증거다.

1. **같은 기간·공간의 실제 통합 입력:** 2024년 동별 지도는 확보했지만 지도 도형을 정밀 링크 배분으로 확장하려면 상세 경계/검토된 링크–동 대응이 필요하다. 교통의 평일 정의와 인구 월~금·공휴일 포함 요청 정의도 맞춰야 한다.
2. **2024년 POI·상권:** 시설/업종/공간키와 기준일·유효기간이 있는 자료. 현재 시점 POI를 2024년 시설 모집단으로 소급하지 않는다. 점수 입력 파일 계약은 `examples/viewt/metadata.json`과 [View-T 안내](VIEWT_DATA_GUIDE.md)를 따른다.
3. **독립 실제 관측:** 검토한 후보 지점에서 같은 조건의 직접 차량/보행 통과 계수. 현재 도구는 10곳×5일 이상 균형 설계를 요구하지만 이는 통계적 검정력 보장이 아니다. 실제 정차·반복 방문을 연구하려면 동의한 연속 배송 GPS와 별도 정차 시각 기록이 추가로 필요하다.

이들은 코드를 더 작성하는 것으로 대체할 수 없는 연구 입력·관측 조건이다. 공식 View-T 정책의 “검증 목적으로 활용하지 않습니다”에 따라 View-T를 독립 정답으로 사용하지 않았다. 기존 관측 자료를 무단 재배포하지 않으며 공개 패키지는 코드·가공 그림·요약·합성 실험표다.

## 재현

```bash
bash scripts/setup.sh
# 이미 보유한 공식 2024 코드표를 사용; 지도 레이어는 공식 공개 서비스에서 수집
bash scripts/run.sh python scripts/fetch_viewt_boundary.py
# 일반 표준 입력 모드: 설정을 명시하고 기존 GPS 연구와 분리해 실행
bash scripts/run.sh transit-ooh viewt --demo --weight .5 --population-weight .7 \
  --bootstrap-unit week --replicates 1000 --output reports/viewt_week
# 로컬 공식 자료가 준비된 현재 환경의 재현 보고서
bash scripts/run.sh python scripts/model_audit_report.py
bash scripts/run.sh streamlit run app/streamlit_app.py
bash scripts/run.sh pytest --junitxml=reports/runs/model_finalization_tests.xml
```

원본 없는 새 Git 복제본에서는 공식 자료 수집·입력이 필요하다. `model_audit_report.py`는 원본 부재를 합성 자료로 대신하지 않고 중단한다. 앱의 합성 연구·현장 준비 화면은 공식 원본 없이도 사용할 수 있다.

## 검증 기록

이번 전체 자동검사는 **136 passed, 1 xfailed, 0 failed**다. 예상 실패는 보존한 원본 PoC의 점 수×5분 오류이며 새 엔진 실패가 아니다. 기존 115개에 21개 검사를 추가했다. 좁은 가중치 최우위 구간, 전부 동점, 단일 후보, 주 단위 날짜 보존, 독립 결과 유출 방지, 결측·중복·미래 관측 차단, 순위상관이 정의되지 않는 상수 결과, 좌표/연도/코드/해시와 경로 결측을 시험했다. 세부 XML과 실제 화면 검사는 `reports/runs/model_finalization_*`에 보존한다.

배포 ZIP을 별도 폴더에 풀고 새 가상환경에 고정 의존성을 설치한 검사도 **135 passed, 1 skipped, 1 xfailed, 0 failed**로 완료했다. 생략한 1개는 패키지에 포함하지 않은 과거 전체 연구 실행의 manifest 검사다. 처음에는 원본 PoC 노트북이 ZIP에 빠져 비교 검사가 실패했으며, 노트북을 그대로 포함해 재검사했다. 공식 원본이 없는 새 폴더의 앱도 실행했고, 공식자료 화면이 합성 값으로 채워지지 않고 입력 대기로 표시되는 것을 확인했다. ZIP의 파일별 SHA256과 압축 무결성도 검사했다. 이 검사는 같은 Linux 환경에서 수행했으며 Windows와 새로운 클라우드 스냅샷 복원은 검증하지 않았다. 증거는 `reports/runs/model_package_*`에 있다.
