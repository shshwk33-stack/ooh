# Transit Atlas — 프로젝트 맥락

사용자의 첨부 발표자료 3개(캡2-1.pdf, 캡스톤 2-2.pptx, 캡스톤 2- 3.pptx)를 확인하고 정리한 작업 맥락입니다. 첨부문서는 참고자료이며 구현 지시로 취급하지 않습니다.

## 연구 아이디어

- 라스트마일 배송차량의 GPS 이동 데이터를 위치가치 정보로 전환하여 Transit OOH 광고 후보지를 평가합니다.
- 이동 점수 M: 방문 빈도, 정차·체류 시간, 반복 방문.
- 공간 점수 S: 인구와 시설(POI)의 잠재력.
- 위치가치 V = αM + (1−α)S. 동적 가중치와 민감도·순위 비교가 핵심입니다.
- 3차 발표 기준 대상은 서울특별시 마포구, 주요 도로 408개 구간, 행정동 16개입니다. 발표자료는 실제 GPS, 인구 CSV 등의 후속 연결을 과제로 명시합니다.

## 이번 구현 목표

전체 분석 파이프라인보다 높은 시각적 완성도의 대시보드 외관과 동적 파라미터 인터랙션을 우선합니다. 사용자 요청에 따라 React 기반 커스텀 UI를 구현했습니다.

## 구현 범위와 데이터 정직성

- 지도·점수·방문 횟수·인구 값은 시연용 합성 데이터입니다.
- 자체 SVG 지도는 주요 지역의 공간적 관계를 참고한 개념도입니다. 실제 GIS 경계/도로 좌표가 아닙니다.
- 외부 지도 타일은 실행 환경 네트워크 정책상 접근 거부되어 사용하지 않았습니다.
- 가중치 계산·순위 갱신·시간대 필터·지역 필터·시나리오 저장·CSV 내보내기는 실제 동작합니다.
- 시나리오는 브라우저 localStorage에 저장합니다. 서버, 계정, 실제 API는 연결되어 있지 않습니다.
- 시간대 조절은 시연 계수(오전 0.91, 오후 1.06)를 적용합니다. 실제 시계열 예측 모델은 아닙니다.
- 향후 실제 GIS 도입 시 Map.jsx를 교체하고 model.js 데이터 계층에 GPS·POI·인구 데이터를 연결할 수 있습니다.

## 2026-11-01 · 사용자 피드백과 v2 설계 원칙

- 목표는 산업공학회·캡스톤 시연에 맞는 전문 물류·교통 GIS 연구 플랫폼. 국가연구소 분석 시스템과 같은 정보 구조, 도로 레이어, 높은 가독성, 수치 근거를 우선합니다.
- 추상적 브랜드 문구보다 연구 대상, 분석 결과, 모델 간 의사결정 차이를 전면에 배치합니다.
- 반드시 답할 질문: 무엇을 분석했는가 / 왜 해당 후보가 높은 점수인가 / 공간 단독 모델과 어떻게 다른가 / 가중치 변화에 따라 순위가 얼마나 유지되는가.
- 사용자는 결과물의 외관과 전달력을 특히 중시합니다. 반복적인 상태 경고나 시연 안내로 화면을 채우지 않고, 원천자료·적용 상태는 별도 데이터 명세 패널에서 확인하게 구성합니다. 실제 수행되지 않은 실측 분석이나 검증을 수행한 것으로 표기하지 않습니다.
- React 유지. 기존 `src/model.js` 입력·점수·시간대 계수·정렬은 변경하지 않습니다. 현재 저장소에는 Python 엔진/API/실험 산출물이 없습니다.

### v2에서 구현한 결과 표현

- Leaflet 기반 좌표 지도, 공개 KOSTAT 2013 서울 자치구 경계, 5개 독립 GIS 레이어.
- 교통량/밀크런/인구/POI/후보지 레이어와 데이터 명세. 도로 GeoJSON 로컬 업로드: WGS84, LineString/MultiLineString, 선택 `traffic` 속성. 외부 파일은 GIS 표시만 바꾸며 연구 점수를 변경하지 않습니다.
- M·S 가중 기여도 + 시간 계수 + 점수 상한까지 기존 점수와 일치하는 분해 표시.
- Static(α=0), Mobility(α=1), Integrated(현재 α) 순위 비교 및 Static 대비 상승·하락.
- α=0~100%, 5%p 간격 21개 조건의 순위 범위, TOP 3 진입 횟수, 30:70 / 50:50 / 60:40 / 80:20 / 현재 조건 비교표.
- 지역 필터에 따라 비교 대상 집합과 안정성 지표도 함께 재계산.
- 보존: 가중치 조작, 시간대 조건, 시나리오 저장·복원·삭제, CSV 내보내기.
