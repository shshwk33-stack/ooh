# 통합 대시보드 변경·검증 보고

2026-11-02. 후보지 평가 화면과 실제 GIS·데이터 연결 화면을 하나의 워크스페이스로 통합했다. 기본 제품 화면에 DEMO·프로토타입 문구나 화면 전환을 두지 않고 자료 출처를 데이터 관리와 후보 상세에서 확인하도록 정리했다.

## 구현 구조

- `UnifiedWorkspace`: 공통 상태, 메뉴, 가중치, 조회 조건, 시나리오, 파일/API 연결, 내보내기.
- `UnifiedMap`: 실제 지리 좌표, 후보·가중치 지도, 행정동 색상, GPS, 선택·레이어·확대·축척.
- `UnifiedPanels`: KPI, 선택 상세, 모델 비교, 민감도, 실제 결과 입력 시 Bootstrap 표시.
- `workspaceContract`: 단일 JSON/CSV/API 입력 계약·검증·취소·시간 초과·용량 제한.
- `workspaceModel`: 단일 V=αM+(1−α)S, 순위·기여도·민감도·모델 비교·GPS 필터·CSV.
- `workspace-default.json`: 파일/API와 동일한 형식의 기본 입력. 이전 표시용 모델·Bootstrap 고정값은 실행 경로에서 제외.

## API·입력

JSON 및 GET API는 schemaVersion 2.0을 사용한다. 후보 CSV는 출처·기간·좌표·M/S를 요구한다. 단위는 metricUnits로 받는다. API가 데이터를 재계산해 반환하면 동일한 검증과 계산·표시 경로를 사용한다. View-T의 엔드포인트나 반환 필드를 가정하지 않았다.

입력 실패 시 현재 자료가 유지된다. 새로운 파일이 느린 API 응답보다 나중에 선택되면 오래된 API가 새 자료를 덮어쓰지 못하도록 취소·요청 순서를 검사한다. 시나리오는 데이터 ID·버전이 맞을 때 복원한다. 데이터 버전은 제공자가 변경사항에 맞게 관리해야 한다.

자료가 없으면 도로 수와 통계 결과를 생성하지 않는다. 실제로 제공된 도로/POI/인구 활동점/안정성 결과를 연결했을 때 활성화하는 양성 입력도 검증했다. 정적 후보 M/S와 GPS 조회 조건은 분리해 근거 없는 시간 배율을 적용하지 않는다.

API 시험은 localhost의 명시적인 모의 응답을 사용했다. 실제 외부 연구 API를 인증해 호출한 것으로 보고하지 않는다. 오프라인 검사는 완성된 HTML 내용을 Chromium에 직접 렌더링하고 네트워크를 차단했다. 이 환경의 정책상 file URL의 더블클릭 자체를 실행한 검사는 아니다.

## 데이터와 기존 프로젝트 영향

실제 공개 경계는 KOSTAT 유래 2013년 일반화 자료다. 후보 점수·수기 앵커와 GPS는 SYNTHETIC 출처로 유지했다. 망원·합정 좌표 순서 오류를 후보 ID 기반 매핑으로 수정하고 행정동 코드와 원문 경계의 covers를 확인했다. 이는 공식 역 위치를 측량한 것이 아니다.

기존 `src/`, `pipeline/`, `public/`와 원천 자료·인증정보·DB는 변경하지 않았다. 기존 화면 코드는 보존하고 `main.jsx` 진입점을 통합 워크스페이스로 바꿨다. 실제 자료 기반 M/S 정규화·방문/정차 추정·Bootstrap 실행은 이번 UI 연결 계층에 임의로 추가하지 않았다.

배포: `TRANSIT_ATLAS_FINAL.html`, 실행 ZIP, 공통 입력 JSON·CSV 양식·데이터 계약, 소스 브랜치. 자료 연결 전용 입력과 표시를 분리했으므로 API·원천 자료를 연결할 때 UI를 다시 설계할 필요는 없다.
